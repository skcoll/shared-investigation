================================================================================
2. KEY FINDINGS
================================================================================

A. STRUCTURED STATE DRAMATICALLY IMPROVES TOOL USAGE

                    Baseline (A+B)    Structured (C+D+E)
    Avg tool calls      4.5              7.8
    Avg unique tools    1.3              3.6
    Avg action gap     0.689             0.245
    run_binary calls    0.3              4.1

The structured agent makes ~2x more tool calls, uses ~3x more unique tools,
and actually runs the binary. The baseline agent barely progresses beyond
file().

B. STRUCTURED AGENT ACTUALLY EXPERIMENTS WITH THE BINARY

run_binary call counts per run:
  Baseline: 0,0,0, 0,0,0 (6 runs total, except A_3 which had 2)
  Structured: 2,1,8, 6,4,7, 4,0,5

The structured agent called run_binary in 8/9 runs.
The baseline called run_binary in 1/6 runs.
This is the critical behavioral difference — the structured agent
treats the binary as something to test, the baseline treats it as
something to describe.

C. ACTION GAP IS REAL AND MEASURABLE

Action gap rate (describes action but doesn't execute):
  A: baseline/none    = 0.600 (60% of steps!)
  B: baseline/light   = 0.778 (78% — interventions made it WORSE)
  C: structured/none  = 0.356
  D: structured/light = 0.156
  E: structured/strong= 0.222

Baseline agents spend most of their budget describing what they would do.
Structured agents actually do it. The visible state with its action history
appears to suppress this "describe but don't execute" pattern.

D. INTERVENTIONS IMPROVE BEHAVIOR WITHIN STRUCTURED CONDITION

Comparing C (no intervention) vs D (light) vs E (strong):
  C: 5.7 tools, 2.7 unique, 0.356 gap
  D: 10.3 tools, 4.3 unique, 0.156 gap  <-- best tool usage
  E: 7.3 tools, 3.7 unique, 0.222 gap

Light interventions (D) produced the most tool calls and lowest action gap.
Strong interventions (E) were slightly less effective, possibly because
the additional specificity about "character pairs" confused the 14B model.

E. INTERVENTIONS HURT BASELINE

Comparing A (no intervention) vs B (light):
  A: 5.7 tools, 1.7 unique, 0.600 gap
  B: 3.3 tools, 1.0 unique, 0.778 gap

Adding interventions to baseline DECREASED tool usage and INCREASED action gap.
Hypothesis: without visible state, the intervention text gets buried in the
growing conversation history. The model responds to the intervention by
describing more analysis rather than executing it, widening the action gap.

F. INTERVENTION UPTAKE

Uptake = intervention fired at step t, tool called at t+1.

  B (baseline/light): 0.22 avg uptake (interventions largely ignored)
  D (structured/light): 0.61 avg uptake (interventions acted on)
  E (structured/strong): 0.28 avg uptake (lower — model confused by specifics?)

Structured state makes interventions actionable. Without state context,
the same intervention text is ineffective.

================================================================================
3. WHY NOTHING SOLVED
================================================================================

The previous experiments that solved used interventions that essentially gave
the answer: "Try: run_binary(abcdefghijklmnop)". The current interventions
are properly designed NOT to reveal the solution.

The 14B model, even with structured state and interventions, cannot independently:
1. Connect strings() output showing strlen + checkSerial to a length hypothesis
2. Systematically test inputs of different lengths
3. Discover the character-pair relationship through behavioral testing

This is a model capability limitation, not a framework failure. The framework
correctly enabled more tool usage and experimentation in structured conditions —
the model just can't close the reasoning gap from "the serial is validated
by checkSerial" to "each character pair must differ by 1".

Predicted fix: a larger model (70B) or a model with stronger code reasoning
would likely solve under condition D or E, given that the structured agent
is already calling run_binary 5-8 times per run.

================================================================================
4. STATISTICAL NOTES
================================================================================

With 0% solve rate across all conditions, statistical tests on solve rate
are uninformative. However, the behavioral metrics show clear patterns:

- Tool diversity: structured > baseline (Mann-Whitney U, all comparisons)
- Action gap: baseline > structured (consistent across all 15 runs)
- run_binary usage: structured >> baseline (8/9 vs 1/6 runs)

These behavioral differences are the story, not solve rate. The paper should
frame this as: "structured state enables the investigation behaviors needed
for solving, even when the model's reasoning is insufficient to complete
the task."

================================================================================
5. RECOMMENDATIONS
================================================================================

1. Run with DeepSeek R1 70B (or Claude) to test if behavioral advantages
   translate to solve rate differences with a more capable model.

2. Add 2 easier challenges where 14B CAN solve (simpler validation logic)
   to get non-zero solve rates for comparison.

3. Consider intermediate metrics: "did the agent discover the serial length?"
   "did the agent test a 16-char input?" — these can show progressive
   understanding even without full solves.

4. Rethink interventions — current ones are too abstract for a 14B model.
   The writeup-derived hints lack the grounding in tool output that would
   make them actionable. See separate discussion on intervention design.
