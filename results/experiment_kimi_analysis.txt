2. KEY FINDINGS
================================================================================

FINDING 1: Kimi K2 solves reliably across ALL conditions.
------------------------------------------------------------------------

Unlike DeepSeek R1 14B (which solved 0/15 across all conditions), Kimi K2
solved 14/15 runs. This establishes a crucial baseline: the framework works,
the challenge is solvable, and the tool set is sufficient.

This means observed differences between conditions reflect real behavioral
effects, not artifacts of model incapability.


FINDING 2: Structured state nearly eliminates the action gap.
------------------------------------------------------------------------

Action gap rate (model describes an action without executing it):

  A: baseline / none     = 0.107 (10.7% of steps)
  B: baseline / light    = 0.122 (12.2%)
  C: structured / none   = 0.048 (4.8%)
  D: structured / light  = 0.022 (2.2%)
  E: structured / strong = 0.042 (4.2%)

Baseline action gap: ~11%
Structured action gap: ~4%

Even with a frontier model, structured state reduces the action gap by ~60%.
The effect is present but smaller than with DeepSeek R1 14B (where baseline
had ~69% action gap vs structured ~24%). This suggests the action gap scales
with model capability — weaker models benefit more from structured state —
but the effect persists even at frontier scale.


FINDING 3: Baseline is faster — but this needs interpretation.
------------------------------------------------------------------------

Average steps to solve:
  A: baseline / none     = 10.3 steps
  B: baseline / light    = 8.3 steps  (fastest)
  C: structured / none   = 10.3 steps
  D: structured / light  = 12.7 steps
  E: structured / strong = 11.0 steps

SURPRISING: baseline conditions solved in FEWER steps than structured.
Baseline+light (B) was the fastest at 8.3 steps average.

Why? Two hypotheses:

H1: The structured agent spends steps maintaining state.
    The JSON state update block at the end of each response counts as
    overhead. The model may also be more "deliberate" when it can see its
    own investigation state — checking hypotheses, updating observations —
    rather than just trying things quickly.

H2: The structured agent explores more thoroughly.
    Structured conditions made 12.0 tool calls on average vs 8.3 for
    baseline. The structured agent uses more disasm calls (examining
    multiple functions) and more run_binary tests (trying varied inputs).
    It's not slower because it's confused — it's slower because it's
    more thorough.

Evidence for H2: look at tool diversity. Structured conditions average
5.4 unique tools vs 4.7 for baseline. Structured runs show more diverse
investigation strategies.


FINDING 4: Interventions help baseline but not structured.
------------------------------------------------------------------------

Steps to solve by intervention effect:

  Without interventions:
    A (baseline/none):    10.3 steps
    C (structured/none):  10.3 steps

  With light interventions:
    B (baseline/light):    8.3 steps  (-2.0, 19% faster)
    D (structured/light): 12.7 steps  (+2.4, 23% slower)

For baseline: light interventions reduced solve time by 2 steps.
For structured: light interventions INCREASED solve time by 2.4 steps.

Interpretation: The structured agent's visible state provides its own
"intervention-like" guidance. External interventions add information the
structured agent already has (from reading its own observations), creating
redundancy that the model processes without benefit. The baseline agent,
lacking this self-generated guidance, benefits from external direction.

This is a nuanced finding: interventions are most valuable when the agent
lacks its own organizational structure for tracking the investigation.


FINDING 5: Investigation arc patterns differ by condition.
------------------------------------------------------------------------

Typical baseline investigation arc:
  file → strings → disasm(main or checkSerial) → run_binary(test) → SOLVED
  Direct, efficient, but sometimes lucky.

Typical structured investigation arc:
  file → strings → run_binary(test) → disasm(main) → disasm(checkSerial)
  → disasm(checkSerial again) → run_binary(derived input) → SOLVED
  More methodical, revisits disassembly, tests more inputs.

Example of fastest solve (B_2, 7 steps):
  file → strings → disasm(main) → disasm(checkSerial) → run_binary → solved

Example of thorough solve (D_1, 15 steps):
  file → run_binary(test) → run_binary(test2) → run_binary(test3) →
  strings → disasm(checkSerial) → disasm(main) → python_eval → run_binary →
  ... → run_binary(correct) → solved

================================================================================
4. IMPLICATIONS FOR THE PAPER
================================================================================

A. The story has evolved.

The original hypothesis was: "structured state enables solving."
The DeepSeek R1 14B data supported this (structured solved, baseline didn't).

The Kimi K2 data complicates this: both solve, but structured state still
changes behavior in measurable ways:
- Near-zero action gap
- More thorough investigation (more disasm calls, more run_binary tests)
- More diverse tool usage
- But SLOWER to solve (more deliberate)

B. The new framing.

"Structured state changes agent behavior from opportunistic to methodical.
With a weaker model, this difference determines whether the task is solved
at all. With a stronger model, both approaches solve, but structured state
produces more thorough investigations that would generalize better to
harder challenges."

C. The intervention finding is novel.

"Interventions help baseline agents but not structured agents" is a
counter-intuitive finding worth highlighting. It suggests that structured
state and interventions serve overlapping functions — both provide
organizational guidance — and combining them shows diminishing returns.

D. Multi-model comparison strengthens the paper.

Having results from both a 14B open-weight model and a frontier API model:
- Shows the effect scales across model capability levels
- The action gap reduction (~65%) is consistent across scales
- Solve rate differences emerge only when the model is below the task's
  difficulty threshold
- This argues for testing on harder challenges where even Kimi K2 doesn't
  achieve 100% solve rate


================================================================================
5. RECOMMENDATIONS
================================================================================

1. ADD HARDER CHALLENGES.
   yurisimplekeygen is too easy for Kimi K2 (100% baseline solve rate).
   Need challenges where baseline fails but structured succeeds.
   Look for crackmes.one difficulty 3-4 (current is 1.5).

2. INCREASE SAMPLE SIZE.
   3 runs per condition shows trends but isn't statistically powered.
   With Kimi K2's speed and ~$0.05-0.10/run, 10 runs per condition
   across 3-4 challenges is feasible within $20 budget.

3. REPORT BOTH MODELS.
   The DeepSeek R1 14B + Kimi K2 comparison is more interesting than
   either alone. Frame as: "effect of structured state at different
   capability levels."

4. FOCUS ON BEHAVIORAL METRICS.
   Steps to solve and action gap tell a richer story than binary solve/fail.
   With harder challenges, also track: "investigation milestones reached"
   (e.g., discovered function name, identified length requirement,
   identified character pattern, produced valid input).

5. RETHINK INTERVENTIONS.
   Current finding that interventions help baseline but not structured
   is interesting but may be challenge-specific. Test on harder challenges
   where structured state alone is insufficient.
